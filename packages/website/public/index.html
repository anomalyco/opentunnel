local service · public address · private traffic

Public URLs for anything.

A CLI and SDK for making apps on your machine reachable from anywhere. TLS terminates locally, so the relay never gets the keys to your traffic. 

$npm i -g @opentunnel/cli
01 / the path

A tunnel the relay can’t look inside.

Visitors connect to a stable public hostname. OpenTunnel reads enough of the TLS handshake to route the connection, then passes the encrypted bytes to your machine.

02 / use it

From localhost to a real URL in three commands.

Create a tunnel once, add as many named routes as you need, and connect. The same behavior is available through the TypeScript SDK.

terminal3 commands
$ opentunnel create
created f7a2mx4kq9vn.opentunnel.xyz

$ opentunnel route add opencode localhost:47365
added opencode.f7a2mx4kq9vn.opentunnel.xyz
   → localhost:47365

$ opentunnel connect
connected · 1 route
created locally
one identity f7a2mx4kq9vn.opentunnel.xyz
one private key stored on this machine · never uploaded
many routes name each local service independently
TypeScript SDK@opentunnel/client
import { create } from "@opentunnel/client"

const client = create()

await client.route.add({ name: "opencode", target: "localhost:47365" })
const connection = await client.tunnel.connect()

console.log(connection.routes[0].hostname)
// opencode.f7a2mx4kq9vn.opentunnel.xyz
03 / under the hood

Five steps. One encrypted connection.

OpenTunnel separates public routing from private decryption. The relay knows where bytes should go, but not what they say.

  1. Reserve

    The CLI reserves a stable tunnel hostname.

  2. Generate

    A private key is created and kept on your machine.

  3. Connect

    The client opens an encrypted bridge to the relay.

  4. Route

    The relay reads the hostname, not the request.

  5. Decrypt

    Your machine terminates TLS and reaches the local app.

04 / boundaries

Private traffic, public address.

The encryption boundary is simple. So are the limits: your URL is reachable by anyone who knows it, and sensitive services still need their own authentication.

01 / encrypted

The relay can’t read traffic.

It forwards TLS bytes without the private key required to decrypt them.

02 / discoverable

Your tunnel hostname is public.

Certificate transparency logs make the base tunnel hostname discoverable.

03 / obscured

Route names stay out of certificates.

The wildcard certificate hides route names from logs, but names can still be guessed.

04 / authenticated

Your services remain responsible for auth.

Anything sensitive behind a tunnel should authenticate every visitor on its own.
